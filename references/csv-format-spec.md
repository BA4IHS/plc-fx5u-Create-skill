# 三菱 FX5U PLC CSV 格式规范

## 编码

- **编码**：UTF-16 Little Endian with BOM (`FE FF` 开头)
- **分隔符**：制表符 (Tab, `\t`)
- **行终止符**：Windows CRLF (`\r\n`)
- **列包围符**：双引号 (`"`)

## 文件结构（固定 3 行表头）

```
"(工程未设置)"
"机型信息:"	"FX5CPU FX5U"
"步号"	"行间声明"	"指令"	"I/O(软元件)"	"空白栏"	"PI声明"	"注解"
```

第 1 行：仅第 1 列有内容 `(工程未设置)`
第 2 行：第 1 列 `机型信息:`，第 2 列 `FX5CPU FX5U`（必须）——注意第1、2列之间有 Tab
第 3 行：7 列标题（必须完整）

## 7 列说明

| 列名 | 内容 | 示例 | 说明 |
|------|------|------|------|
| 步号 | 数字或空 | `"0"`, `"2"`, `""` | 指令行有数字，参数行留空 |
| 行间声明 | 通常为空 | `""` | 预留给特殊声明 |
| 指令 | PLC指令 | `"LD"`, `"SET"`, `"OUT"` | 指令助记符 |
| I/O(软元件) | 地址/参数 | `"X0"`, `"M10"`, `"K50"` | 软元件或参数值 |
| 空白栏 | 通常为空 | `""` | 保留列 |
| PI声明 | 通常为空 | `""` | 预留给 PI 声明 |
| 注解 | 必须为空 | `""` | **禁止填入任何文本**。填入内容会导致 GX Works3 导入报错 |

## 多行格式变体

### 扩展格式

定时器/计数器的 OUT 指令和参数分开两行：
```
"8"	""	"OUT"	"T1"	""	""	""    ← 指令行，有步号
""	""	""	"K10"	""	""	""       ← 参数行，步号为空
"13"	""	"LD"	"T1"	""	""	""   ← 下一指令行
```

规则：
- 指令行有步号（数字）
- 参数行步号为 `""`（空字符串），紧跟对应的指令行
- 参数行的"指令"列为空，参数值出现在"I/O(软元件)"列
- 适用于：`OUT Tx` → `Kxx`、`OUT Cx` → `Kxx` 等

### 三行扩展格式（特殊指令）

**ANS 报警器指令**占用 3 行：
```
"2"	""	"ANS"	"T0"	""	""	""     ← 指令行: 内部用定时器
""	""	""	"K20"	""	""	""        ← 参数行: 判断时间
""	""	""	"F0"	""	""	""         ← 参数行: 报警器号
```

- 第 1 行：`ANS Tn`（Tn 为内部判断用定时器）
- 第 2 行：`K 值`（判断时间，100ms 时基）
- 第 3 行：`F 号`（报警器编号）
- 定时器号不可与其他已使用的定时器冲突

### 三行运算格式

ADD / ADDP / SUB / MUL / DIV / *P 等算术指令占用 3 行：
```
"1159"  ""  "ADDP"  "D30"   ""  ""  ""   ← 指令行: 指令 + 操作数1
""      ""  ""      "K1000" ""  ""  ""   ← 参数行: 操作数2
""      ""  ""      "D30"   ""  ""  ""   ← 参数行: 结果目标
```

### 六行 MODBUS 格式

ADPRW 通信指令占用 6 行：
```
"166"  ""  "ADPRW"  "K10"   ""  ""  ""    ← 站号
""     ""  ""       "K3"    ""  ""  ""    ← 功能码
""     ""  ""       "K3"    ""  ""  ""    ← 从站地址
""     ""  ""       "K2"    ""  ""  ""    ← 读/写数量
""     ""  ""       "D100"  ""  ""  ""    ← 数据寄存器
""     ""  ""       "M100"  ""  ""  ""    ← 状态寄存器
```

### MC/MCR 格式

MC 指令占用 2 行：
```
"19"  ""  "MC"   "N0"    ""  ""  ""     ← 指令行: 嵌套层级 N0~N7
""    ""  ""     "M998"  ""  ""  ""     ← 参数行: 嵌套用 M
```
MCR 指令 1 行：`"N0"` 与 MC 对应。

### 四行 FROM/TO 格式

FROM/TO 模块读写指令占用 4 行：
```
"150"  ""  "FROM"  "K0"    ""  ""  ""    ← 指令行: 模块号（0~7）
""     ""  ""      "K29"   ""  ""  ""    ← 参数行: BFM 号
""     ""  ""      "D10"   ""  ""  ""    ← 参数行: 目标/源寄存器
""     ""  ""      "K1"    ""  ""  ""    ← 参数行: 读取/写入字数
```

### 紧凑格式（历史兼容）

所有参数与指令同行：
```
"18"	""	"OUT"	"Y1"	""	""	""
"20"	""	"OUT"	"T0"	"K50"	""	""   ← K50 在软元件列
```

## 常数值表示

| 类型 | 格式 | 示例 | 说明 |
|------|------|------|------|
| 十进制 | K | `K10`, `K-16`, `K-600` | 支持负数 |
| 十六进制 | H | `H0D`, `HFF` | 十六进制常数 |
| 浮点数 | E | `E1.23`, `E-4.56` | 浮点数常数 |

## 步号规则

- 起始步号为 `"0"`
- 递增不重复即可，GX Works3 导出可使用奇数（如 19, 37, 43 等）
- 生成时统一使用偶数递增（0, 2, 4, 6, 8, ...）以保证兼容性
- 参数行步号为 `""`（空字符串）
- 步号不可重复（参数行除外）

## 文件生成代码模板

```python
import codecs

def write_plc_csv(rows, output_path):
    """将程序行写入 UTF-16LE CSV 文件"""
    with open(output_path, 'wb') as f:
        # BOM
        f.write(b'\xff\xfe')

        # 表头 3 行
        content = []
        content.append('"(工程未设置)"\r\n')
        content.append('"机型信息:"\t"FX5CPU FX5U"\r\n')
        content.append('"步号"\t"行间声明"\t"指令"\t"I/O(软元件)"\t"空白栏"\t"PI声明"\t"注解"\r\n')

        # 数据行
        for row in rows:
            line = '\t'.join(f'"{col}"' for col in row)
            content.append(line + '\r\n')

        # 编码为 UTF-16LE 写入
        for line in content:
            f.write(line.encode('utf-16-le'))
```

## 导入注意事项

- GX Works3 完全支持两种格式
- **注解列必须为空**：第 7 列填入任何内容都会导致 GX Works3 报错"无法读取软元件"或"梯形图配置不正确"
- 如果导入失败，检查：BOM 是否存在、是否使用 Tab 分隔、步号是否重复、注解列是否为空
- Notepad++ 查看需设置为 "UTF-16LE" 编码
- Excel 导入需选择 UTF-16LE 编码和制表符分隔
